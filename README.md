# GitGo

Git-клиент для Android с отправкой в GitHub: выбор файлов и папок через проводник, быстрая загрузка,
уведомления со скоростью, темы, встроенный терминал с git-командами. Kotlin + Jetpack Compose + JGit.

## Сборка на GitHub
1. Создайте репозиторий и загрузите содержимое этой папки (вместе с `.github/`).
2. Вкладка **Actions → Build GitGo** запустится сама (или Run workflow).
3. В конце скачайте артефакт **GitGo-apk-aab**: `app-debug.apk` для установки, `app-release.aab` для Google Play.

### Подпись для Google Play (Settings → Secrets and variables → Actions)
`KEYSTORE_BASE64` (keystore в base64: `base64 -w0 release.jks`), `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
Без них release собирается без подписи — для Play нужен подписанный AAB.

## Как пользоваться
0. Язык интерфейса: English / Русский / 中文 (по языку системы).
1. При первом запуске — GIF-заставка и три экрана знакомства (раскрытие доступа к файлам, разрешение на уведомления).
2. Создайте токен на github.com/settings/tokens (право `repo`) и вставьте на главном экране.
3. Клонируйте репозиторий (иконка облака) или создайте новый («Новый репозиторий»).
4. Внутри репозитория: **Файлы → Файлы / Папку** — выберите в проводнике, что добавить (копируется в репозиторий).
5. **Изменения → Отправить на GitHub** — коммит и загрузка. Прогресс, скорость и оставшееся время — в уведомлении.
6. Значок терминала открывает отдельное окно (`help` — список команд).

## Что добавлено сверх запроса
Pull/Push/Commit вручную, история, ветки (создание и переключение), создание репозиториев на GitHub,
отмена передачи из уведомления, режимы отправки Авто/API/Git, автор коммитов, быстрые кнопки в терминале,
`git send` в терминале, защита от выхода за пределы папок при импорте, шифрованное хранение токена.

## Новые возможности
- **CI (вкладка «CI» в репозитории):** запуски GitHub Actions, задачи, логи упавших шагов (прыжок к первой ошибке, копирование), кнопки «Re-run failed jobs», «Re-run all», «Cancel». Нужен токен с правами repo и workflow/actions.
- **Виджеты:** график вкладов, статус CI закреплённого репозитория (меню репозитория → «Закрепить CI на виджете»), PR, ожидающие вашего ревью. Нажатие по виджету обновляет его; также обновление раз в 30 минут и при выходе из приложения.
- **Diff и быстрая правка:** вкладка «Изменения» → нажмите файл: построчный diff с подсветкой синтаксиса, нажатие на строку правит её на месте; кнопка-карандаш открывает редактор файла. В «Файлах» нажатие на файл открывает редактор.
- **Хранилище (Настройки → Хранилище):** защита токена отпечатком (ключ Android Keystore, приложение блокируется при выходе более чем на минуту), генерация SSH-ключей Ed25519 (копирование публичного ключа, добавление в GitHub, выдача закрытого ключа только после отпечатка).
- **Открыть в…:** меню репозитория (три точки) → «Открыть папку в…», «Открыть в Acode», «Экспорт копии в папку…». Репозитории также видны в системном выборе файлов как хранилище «GitGo» — редакторы с поддержкой SAF (Acode и др.) могут открыть папку и править файлы. Для Termux используйте экспорт копии в общую папку и `~/storage/shared`.

## Google Play — чек-лист
- targetSdk 36 (требование Play для новых приложений и обновлений с 31.08.2026).
- Нет `MANAGE_EXTERNAL_STORAGE` и прочих широких разрешений; файлы — только через системный выбор (SAF).
- Foreground-сервис типа `dataSync` — в Play Console заполните декларацию, опишите передачу файлов в GitHub.
- Разместите `PRIVACY_POLICY.md` по публичной ссылке и замените `PRIVACY_URL` в `Screens.kt` (YOUR_NAME).
- Data safety: данные не собираются разработчиком; токен хранится на устройстве, передаётся только GitHub.
- Не используйте логотип GitHub и слово GitHub в названии; в описании укажите, что приложение неофициальное.
- Графика для магазина — в папке `store/` (иконка 512, feature graphic 1024×500).
- Подтвердите права на логотип и GIF (если создавали нейросетью — проверьте условия сервиса).
- Новые личные аккаунты разработчика требуют закрытого тестирования перед публикацией (проверьте актуальные правила Play).

## Хранение
Репозитории лежат во внутренней памяти приложения (`files/repos`): там работают права доступа, символьные ссылки и различие регистра в именах файлов (в «общей» памяти этого нет). Другие приложения видят их только через хранилище «GitGo» в системном выборе файлов или через экспорт копии.

## Версия JGit
Используется JGit 7.8.0 (Java 17, включён core library desugaring). Если на Android 8–10 появятся `NoSuchMethodError`, в `app/build.gradle.kts` замените версию на `6.10.1.202505221210-r` или `5.13.3.202401111512-r` — код приложения совместим со всеми тремя.

## Ограничения
- Сам GitGo работает с GitHub по HTTPS и токену. SSH-ключи генерируются и хранятся для GitHub и других инструментов; передача Git по SSH внутри приложения не реализована.
- Виджеты не могут читать токен, пока приложение заблокировано биометрией: они показывают последние сохранённые данные и обновляются после разблокировки.
- Токену для списка вкладов, CI и ревью нужны соответствующие права; для добавления SSH-ключа — admin:public_key.
- Терминал — встроенная git-консоль на JGit, а не полный Linux-шелл как Termux.
- Быстрая отправка через API работает, если локальная ветка совпадает с удалённой (иначе используется git push);
  файл не больше 100 МБ (лимит GitHub).
- У clone/push через JGit показываются проценты и «об/с»; точные МБ/с — при отправке через API и при копировании.
- Языки интерфейса: English (по умолчанию), Русский, 简体中文. Язык берётся из системы; на Android 13+ его можно выбрать отдельно для приложения (Настройки → Язык). Строки лежат в `app/src/main/res/values*/strings.xml` — новый язык добавляется копией папки `values` и строкой в `res/xml/locales_config.xml`. Традиционный китайский пока показывается в упрощённом написании.
